# Requirement coverage: ข้อ 4.6 Portal ผู้พัก

หลัง Login ระบบตรวจ `tenant_id` ของบัญชี หากเป็นบัญชีนักศึกษา บุคลากร หรือบุคคลภายนอก จะเปิด `TenantPortal` แทน Dashboard เจ้าหน้าที่โดยอัตโนมัติ

| ข้อ | การพัฒนา |
|---|---|
| 4.6.1 ตรวจข้อมูลหนี้ของตนเอง | `GET /api/invoices` กรองด้วย `tenant_id` จาก token เท่านั้น พร้อมดาวน์โหลดใบแจ้งหนี้และใบเสร็จของตนเอง |
| 4.6.2 ส่งหลักฐานของตนเอง | `POST /api/payment-proofs` ตรวจว่าใบแจ้งหนี้เป็นของผู้ใช้ก่อนรับ JPG, PNG หรือ PDF และปฏิเสธแบบ `403` เมื่ออ้างใบแจ้งหนี้คนอื่น |
| 4.6.3 ตรวจข้อมูลการเช่าของตนเอง | `GET /api/contracts` และ document endpoint ตรวจเจ้าของสัญญาจาก token ทุกครั้ง |
| 4.6.4 แจ้งซ่อมของตนเอง | `GET /api/repairs` กรองเฉพาะผู้เช่า และ `POST /api/repairs` ผูกห้องจากเตียงที่กำลังพักในฐานข้อมูล ไม่เชื่อถือ `roomId` ที่ Portal ส่งมา |

## หน้าเว็บ

- Route หลัง Login แยกตามชนิดบัญชีใน `App.jsx`
- `TenantPortal` มี 4 พื้นที่: หนี้ของฉัน, ส่งหลักฐาน, การเช่าของฉัน และแจ้งซ่อม
- แถบสถานะการพักแสดงห้อง สัญญาปัจจุบัน และยอดค้างจาก `GET /api/tenant-portal/summary`
- หน้า Portal ไม่มีเมนูจัดการผู้ใช้ การเงินส่วนกลาง รายงาน หรือข้อมูลผู้เช่าคนอื่น

## การทดสอบสิทธิ์

Integration test สร้างผู้เช่า 2 คน แล้วตรวจว่าบัญชีคนแรก:

- ไม่เห็นใบแจ้งหนี้และงานซ่อมของคนที่สอง
- แนบหลักฐานให้ใบแจ้งหนี้ของคนที่สองไม่ได้
- เปิดรายละเอียดงานซ่อมของคนที่สองไม่ได้
- ส่ง `roomId` ที่ไม่ได้พักมาเองไม่ได้ ระบบใช้ห้องจากฐานข้อมูลเท่านั้น
