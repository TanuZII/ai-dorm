# Requirement coverage: ข้อ 4.4 การบริหารจัดการห้องพัก
เอกสารนี้เชื่อมข้อกำหนดกับหน้าจอ, API และข้อมูลที่ระบบจัดเก็บ เพื่อใช้ตรวจรับงาน

| ข้อ | ความสามารถ | การพัฒนา |
|---|---|---|
| 4.4.1 | ตรวจห้องว่างตามอาคาร ชั้น หรือทั้งหมด | `GET /api/rooms` รองรับ `buildingId`, `floor`, `availability` |
| 4.4.2 | ตรวจเตียงว่างตามอาคาร ชั้น จำนวนเตียงต่อห้อง | `GET /api/beds` รองรับ `buildingId`, `floor`, `bedCount`, `availability` |
| 4.4.3 | จองเป็นเตียงหรือทั้งห้อง | `POST /api/reservations` ตรวจผู้เช่า ความพร้อมห้อง และความว่างแบบ transaction พร้อมเก็บเงื่อนไข Rate Policy ณ เวลาจอง |
| 4.4.4 | ย้ายห้อง | `POST /api/room-transfers` เก็บเตียงเดิม/ใหม่ วันที่ เหตุผล และปรับสัญญาปัจจุบันแบบ transaction |
| 4.4.5 | ย้ายออก | `POST /api/checkouts` เก็บวันที่ ความเสียหาย หนี้คงค้าง เงินประกัน และยอดคืน พร้อมคืนสถานะเตียง |
| 4.4.6 | ตรวจความพร้อมห้อง | `POST /api/rooms/:id/readiness` เก็บ checklist ผู้ยืนยัน เวลา และป้องกันการเปิดจองเมื่อมีเตียงเสียหายหรืองานซ่อมค้าง |
| 4.4.7 | มิเตอร์ไฟและค่าไฟรายเดือน | `POST /api/meter-readings` ประเภท `electricity` คำนวณยอดตามหน่วยและหารด้วยจำนวนเตียง |
| 4.4.8 | มิเตอร์น้ำและค่าน้ำรายเดือน | API เดียวกัน ประเภท `water`; สร้างใบแจ้งหนี้แยกรายคนอัตโนมัติ |
| 4.4.9.1 | เจ้าหน้าที่รับแจ้งซ่อม | `POST /api/repairs` ระบุ `source=staff`, ชื่อผู้แจ้ง และผู้เช่าได้ |
| 4.4.9.2 | ผู้เช่าแจ้งผ่านระบบ | สิทธิ์ `repairs.create`; ระบบผูก `tenant_id` จากบัญชีที่เข้าสู่ระบบ |
| 4.4.9.3 | รายละเอียดและประวัติ | `GET /api/repairs/:id` คืนข้อมูลผู้แจ้ง ห้อง timeline และประวัติเบิกอุปกรณ์ |
| 4.4.9.4 | Update สถานะซ่อม | `POST /api/repairs/:id/updates` รองรับ รอเข้าซ่อม, ระหว่างซ่อม, รออะไหล่, ซ่อมเรียบร้อย |
| 4.4.9.5 | ปิดงาน | สถานะ `closed` ทำได้หลัง `completed` และเก็บผู้ดำเนินการ/เวลาใน Audit Log |

## กติกาที่ใช้

- “พร้อมจอง” หมายถึงห้องผ่านการตรวจความพร้อม, ห้องไม่อยู่สถานะชำรุด/ไม่พร้อม และเตียงเป้าหมายว่าง
- การจองทั้งห้องจะสำรองทุกเตียงในห้องพร้อมกัน หากมีเตียงใดไม่ว่างจะไม่จองบางส่วน
- ค่าสาธารณูปโภคคำนวณ `จำนวนหน่วย × อัตราต่อหน่วย ÷ จำนวนเตียงทั้งหมดในห้อง` ตามข้อกำหนด และออกหนี้เฉพาะผู้พักที่ผูกกับเตียงในเดือนนั้น
- ยอดคืนประกันเบื้องต้นคำนวณ `เงินประกัน - ค่าเสียหาย` โดยแสดงหนี้คงค้างแยกต่างหากเพื่อให้เจ้าหน้าที่ตรวจสอบก่อนคืนเงินจริง
- การเบิกอุปกรณ์เข้าประวัติงานซ่อมจะตัดสต็อกและสร้าง inventory movement ใน transaction เดียวกัน

## หน้าจอ

`apps/web/src/containers/RoomOperations/RoomOperations.jsx` แบ่งเป็น 3 พื้นที่:

1. ห้องและเตียงว่าง — ตัวกรองอาคาร ชั้น ขนาดห้อง และสถานะพร้อมจอง
2. งานเข้าพัก — จอง ย้าย ย้ายออก และตรวจความพร้อม
3. มิเตอร์รายเดือน — บันทึกเลขมิเตอร์ อัตรา วันครบกำหนด และสร้างใบแจ้งหนี้
