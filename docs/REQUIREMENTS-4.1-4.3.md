# Requirement Coverage 4.1–4.3

## 4.1 ข้อมูลพื้นฐาน

ระบบใช้ `master_data` ซึ่งรองรับหมวด, code, ชื่อ, parent–child, metadata, สถานะ และเหตุผลการยกเลิก ครอบคลุม:

- คำนำหน้าชื่อ ประเทศ จังหวัด อำเภอ ตำบล และรหัสไปรษณีย์
- ประเภทผู้เช่า ประเภทห้อง อาคาร ห้อง เตียง และปีการศึกษา
- ประเภทการเช่า ประเภทสัญญา และรายการค่าธรรมเนียม
- คณะและสาขาวิชา

หน้า “ข้อมูลพื้นฐาน” อ่านข้อมูลจริงจาก API และรองรับเพิ่ม แก้ไข และยกเลิกพร้อมเหตุผล โดยฟอร์มห้องเก็บอาคาร/ชั้นผ่านข้อมูลแม่ เลขที่ห้อง ชื่อห้อง และจำนวนเตียง ส่วนฟอร์มเตียงเก็บห้องแม่และลำดับเตียง

รองรับ CRUD รายการเดี่ยวและ bulk import สูงสุด 10,000 แถวต่อ request ผ่าน:

```text
GET    /api/master-data/:category
POST   /api/master-data/:category
POST   /api/master-data/:category/import
PATCH  /api/master-data/:category/:id
DELETE /api/master-data/:category/:id
```

การลบเป็นการยกเลิกใช้งานและบังคับเหตุผล รายการที่มีข้อมูลลูกใช้งานอยู่จะยกเลิกไม่ได้

ข้อมูลจังหวัด อำเภอ ตำบล และรหัสไปรษณีย์ฉบับเต็มต้องนำเข้าจากไฟล์มาตรฐานที่มหาวิทยาลัยอนุมัติ ระบบไม่สร้างข้อมูลที่อยู่นอกเหนือเอกสารโดยการคาดเดา

## 4.2 นโยบายจัดเก็บ

ตาราง `rate_policies` จัดเก็บนโยบายแบบมีช่วงเวลาบังคับใช้ โดยประกอบด้วย:

- cohort ผู้เช่าและรอบการเช่า
- คิดต่อคนหรือต่อห้อง และจำนวนผู้พักสูงสุด
- ค่าเช่า ตัวหารค่าสาธารณูปโภค ค่าน้ำ ค่าไฟ และเงินประกัน
- วันครบกำหนด ค่าปรับ จำนวนเดือนค้าง และเงื่อนไขยุติสัญญา
- วันเริ่ม–สิ้นสุด สถานะ และเหตุผลยกเลิก

Seed ตามข้อกำหนดแล้วสำหรับนักศึกษา 68+, นักศึกษา 64–67, บุคลากร และบุคคลภายนอก รวมกรณีเหมาห้อง ภาคฤดูร้อน รายเดือน รายภาคเรียน และรายปี

API:

```text
GET   /api/rate-policies
POST  /api/rate-policies
PATCH /api/rate-policies/:id
```

สัญญารองรับสร้าง แก้ไข ยกเลิก ต่อสัญญา และรายงาน:

```text
GET   /api/contracts
POST  /api/contracts
PATCH /api/contracts/:id
POST  /api/contracts/:id/renew
GET   /api/reports/contracts
```

## 4.3 ผู้ใช้งานและสิทธิ์

- ผู้ใช้และกลุ่มที่ยกเลิกจะใช้ soft-delete พร้อมเหตุผลและ Audit Log
- สิทธิ์จัดการผ่าน role permissions
- เจ้าหน้าที่สร้างบัญชี Portal แทนนักศึกษา/ผู้เช่าได้
- Student Service adapter ตอบสถานะ `INTEGRATION_NOT_CONFIGURED` จนกว่าจะได้รับ URL และ credentials จริง
- History Log กรองตาม username, action, entity, from และ to
- Local password ต้องมีอย่างน้อย 8 ตัวอักษร พร้อมอักษรพิมพ์ใหญ่ พิมพ์เล็ก และอักขระพิเศษ
- Local password เก็บด้วย bcrypt cost 12 ส่วน LDAP password ไม่ถูกจัดเก็บ
- หน้า “ผู้ใช้และสิทธิ์” เชื่อม API จริงสำหรับผู้ใช้ กลุ่ม permission assignments บัญชี Portal รีเซ็ตรหัสผ่าน เปลี่ยนรหัสผ่านตนเอง และ History Log ที่กรองตามชื่อผู้ใช้/ช่วงวันที่
- สถานะ LDAP/AD แสดงจาก configuration จริงของ Backend และไม่แสดงสถานะพร้อมเชื่อมต่อเมื่อยังไม่ได้กำหนด Environment
